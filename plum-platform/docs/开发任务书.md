# 开发任务书 · 大邑䢺江镇青梅产业农商文旅综合平台

> 本文是**可直接用于开发实现与验收**的任务书：功能编号唯一、输入输出明确、边界条件可测、验收标准可判定。实现基线为仓库中的 `server/`、`web/`、`mp-weixin/`、`tests/` 与 `start.py`。
>
> 本项目为本地一体化交付：不接外部模型、外部地图、消息推送或支付网关，因此任务书中不涉及任何访问凭据、账号配置或密钥管理内容。

## 1. 项目目标与范围

### 1.1 目标

把「青梅种植—采摘体验—酿酒研学—民宿住宿—农特产品—文化节庆」串成一条线：游客在小程序或 H5 上完成浏览、预约、报名、预订、下单、集章；农户与民宿店家在 H5 工作台排场次、调房间、管商品、发货、核销；镇平台在 PC 后台审核、发布活动、看销售与预约走势。三端共用一本账，状态只有一份。

### 1.2 交付范围

| 编号 | 端 | 形态 | 交付内容 |
| --- | --- | --- | --- |
| S1 | 游客端 | 微信小程序 + H5 | 首页、地图点位、采摘预约、酿酒研学、民宿预订、农特商城、文化节、时令提示、打卡集章、我的单据、AI 四项能力 |
| S2 | 商户端 | H5 工作台 | 工作台统计、场次管理、房间管理、商品管理、订单发货、三类业务统一核销 |
| S3 | 管理后台 | PC Web | 数据看板、商户审核、场次审核、商品审核、活动发布与上下线、订单/预约台账、账号与操作记录 |
| S4 | 服务端 | Flask + SQLite | 四组 API、21 张表、统一状态机、统一响应/校验/分页/幂等/日志 |
| S5 | 工程交付 | 脚本与文档 | 一键自启动、端到端验收脚本、统一图片与图表规格、完整目录与运行说明 |

### 1.3 不在本次范围

线上支付清算、短信与消息推送、GIS 在线底图、多租户权限模型、外部大模型推理、生产级高可用部署、数据迁移工具。这些均不影响 1.2 中全部闭环的实现与验收。

## 2. 全局技术约定（所有端必须遵守）

### 2.1 统一响应

成功与业务失败都返回 JSON：

```json
{ "code": 200, "msg": "success", "data": { } }
```

`data` 为对象、数组或 `null`。业务错误默认 HTTP 200，由 `code` 判定；HTTP 层错误才用对应状态码。

| code | 含义 | 触发示例 |
| --- | --- | --- |
| 200 | 成功 | 任意正常请求 |
| 400 | 参数格式不对 | 缺必填项、字段超长、状态值非法 |
| 401 | 未登录或会话失效 | 未带会话头访问需登录接口 |
| 403 | 身份不符 | 游客访问后台接口 |
| 404 | 资源不存在 / 接口不存在 | 未知路径、查不到订单 |
| 405 | 请求方法不对 | 对只读接口发 POST |
| 409 | 状态冲突 / 重复操作 | 重复核销、重复审核、同一天重复盖章 |
| 422 | 业务规则不满足 | 名额已满、库存不足、驳回未写原因 |
| 500 | 服务异常 | 未捕获异常，统一兜底文案 |

业务提示一律说人话，例如「驳回得写一句原因，商户好改」「这枚章今天已经盖过啦」。

### 2.2 会话

`POST /api/auth/login` 返回 `sessionId`；后续请求放在请求头 `X-Session-Id`。三端与小程序完全一致。会话保存在服务进程内存，服务重启后失效，前端收到 401 应清除本地会话并跳转登录。

登录可传 `role`，与账号实际角色不符时返回 403，防止从错误入口进入。

### 2.3 分页

列表接口统一使用 `pageNum`（默认 1，最小 1）、`pageSize`（默认 20，范围 1~100），返回：

```json
{ "records": [], "total": 0, "current": 1, "size": 20 }
```

不分页的接口直接返回数组。

### 2.4 金额

- 数据库一律以**分**为整数存储（字段名 `*_cent`）。
- 对外统一由 `public_amount()` 转成两位小数**字符串**，字段名去掉 `_cent`（`price_cent → price`，`amount_cent → amount`）。
- 前端只展示字符串，不做浮点运算；金额求和在服务端以整数分完成。

### 2.5 幂等

写操作要求 `requestId`（客户端生成的非空字符串）。服务端在内存中保留 5 分钟，命中则直接返回首次结果，不重复扣库存、不重复生成单号。重复提交同一 `requestId` 返回与首次完全相同的结果。

### 2.6 时间、单号与核销码

- 时间格式 `YYYY-MM-DD HH:MM:SS`，日期 `YYYY-MM-DD`。
- 业务单号：`PM`（订单）、`YY`（预约）等前缀 + 当天日期 + 4 位序号。
- 核销码：`CK` + 10 位大写十六进制，采摘预约、研学报名、民宿预订三类业务共用。

### 2.7 统一状态机

唯一实现位于 `server/state_machine.py`，任何端不得自行改写状态流转规则。

| 组 | 允许迁移 |
| --- | --- |
| `order` 订单 | 待支付→已支付/已取消；已支付→已发货/已退款；已发货→已完成；已完成/已取消/已退款 终态 |
| `booking` 预约类 | 待核销→已核销/已取消/已过期；其余终态 |
| `audit` 审核 | 待审核→已通过/已驳回；已驳回→待审核（商户修改后重新提交）；已通过 终态 |
| `shelf` 上下架 | 上架↔下架 |

非法迁移返回 409，同状态重复操作返回 409，并给出当前允许的目标状态列表。

### 2.8 图片规格

- 素材集中在 `assets/`，共 33 张，统一 WebP/PNG、统一裁切与色调。
- H5/后台只允许三种比例：`.img-16-9`（横幅、活动）、`.img-4-3`（列表、卡片）、`.img-1-1`（缩略图），统一 `object-fit: cover` 与统一占位图。
- 小程序 `app.wxss` 定义同样的三种比例与同一套配色，图片路径由 `asset()` 统一拼成服务绝对地址。
- 任何图片加载失败都回落到内置占位图，不出现破图。

### 2.9 图表规格

- 后台看板所有图表统一返回 `{labels: string[], series: [{name: string, data: number[]}]}`。
- 前端只有 `Charts.draw(container, chart, type)` 一个渲染器，固定画布 `640×220`、固定 4 色、固定网格与字号。
- 柱状图与折线图共用网格、坐标与图例；数据未攒够时显示统一空态，不画空坐标系。

### 2.10 文案风格

- 用镇上人说话的短句，避免「赋能、助力、一站式、为您提供、匠心」等机械套话；`api_ai.py` 的 `polish()` 负责清洗。
- AI 回答中的名称、价格、余位、时间必须来自业务库实时查询，不允许编造，并在响应里标注 `source`。
- 回答不了时诚实兜底并给出可问的示例问题，不硬凑答案。

## 6. 关键闭环流程

### 6.1 采摘预约与核销

```
游客 H5/小程序 选场次 → POST /api/reservations
  → 校验场次已审核 / 可预约 / 余位足够 / 人数与手机合法
  → 占用名额、生成预约码与 CK 核销码、状态「待核销」、写操作日志
后台 GET /api/admin/reservations 看到同一条记录
商户工作台 GET /api/merchant/bookings 看到待核销列表
到场 → POST /api/merchant/checkin {checkin_code}
  → 遍历三张业务表定位 → booking 状态机 待核销→已核销
游客「我的」与后台看到「已核销」；重复核销返回 409
```

### 6.2 商城订单与发货

```
游客 加购/直接购买 → POST /api/orders（requestId 幂等）
  → 扣库存、加销量、生成订单明细、清购物车、状态「待支付」
→ POST /api/orders/<id>/pay → 状态「已支付」
商户 POST /api/merchant/orders/<id>/ship → 状态「已发货」
后台看板只把「已支付/已发货/已完成」计入销售额
游客取消（待支付）→ 回滚库存与销量、状态「已取消」
```

### 6.3 审核与活动发布

```
商户新增场次/商品 → 状态「待审核」，游客端不可见
后台 POST /api/admin/{merchants|sessions|products}/<id>/audit
  → 通过：商品自动「上架」；驳回：必须写原因，状态「已驳回」
后台 POST /api/admin/festivals → 活动「展示中」→ 游客端首页立即可见
所有审核、发布都写入 operation_logs
```

## 7. 边界条件汇总（必须逐条覆盖）

| 类别 | 规则 |
| --- | --- |
| 入参类型 | 整数解析拒绝布尔值与小数伪装；字段长度、必填项统一校验 |
| 人数 / 数量 | 预约 1~20 人；购物车与直接购买 1~99 件；民宿人数不超过房型容量 |
| 联系方式 | 手机必须 11 位纯数字；联系人 ≤20 字 |
| 地址 | ≤100 字；审核意见 ≤100 字；活动名 ≤40 字、介绍 ≤200 字；AI 问题 ≤200 字 |
| 日期 | 民宿离店必须晚于入住、最多 30 晚；场次只展示今天及以后 |
| 库存 / 名额 | 库存不足、名额已满整单/整次失败，返回 422 |
| 状态 | 非法迁移、重复支付、重复发货、重复审核、重复核销返回 409 |
| 幂等 | 同一 `requestId` 5 分钟内返回首次结果，不产生第二条记录 |
| 打卡 | 同一用户同一天同一点只能盖一次，重复 409 |
| 权限 | 未登录 401；角色不符 403；只能查看自己的单据；只有管理员可进后台 |
| 路由 | 未知 `/api/*` 返回 404；方法不匹配返回 405；预检请求返回 204 且不抢占 404 匹配 |
| 图片 | 加载失败回落占位图；不使用外部图床 |
| 数据 | 金额以整数分计算；除零与空结果返回空态而不是报错 |
| 服务重启 | 会话清空；`--reset` 可重建基准数据，验收结果可复现 |

## 9. 验收方案与完成标准

**通过标准：全部检查项通过，退出码 0，无 5xx、无未捕获异常。**

### 9.2 手工三端巡检

| 端 | 巡检项 | 通过标准 |
| --- | --- | --- |
| 门户 `/` | 三个入口、说明矩阵、账号、健康检查链接 | 全部可达 |

## 11. 假设与待确认

- 部署形态为本地/局域网单机演示，会话存内存，重启后需重新登录；若上生产需换成持久会话。
- 支付为演示态（状态机迁移），不接真实支付渠道；退款、对账、发票不在本期。
- 地图为包内本地地形示意底图 + 标定锚点点位，不接在线底图；如需真实坐标、导航与路径规划，需另行接入地图服务及密钥。
- 语音讲解在 H5 用浏览器自带语音合成，小程序展示讲解稿全文；如需小程序内朗读，需另接语音能力。
- 演示账号口令为本地初始化写入，上线前必须替换为正式账号体系与口令策略。
