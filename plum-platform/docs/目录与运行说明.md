# 目录与运行说明

本文逐文件说明交付内容，并给出从零安装、启动、导入小程序、验收、排错的完整步骤。所有命令都在**项目根目录**（即 `start.py` 所在目录）执行。

---

## 1. 目录总览

```
plum-platform/
├── start.bat                     Windows 一键启动
├── start.py                      跨平台启动入口
├── requirements.txt              依赖清单（仅 Flask）
├── README.md                     项目总览
├── docs/                         本文档 + 开发任务书
├── server/                       后端源码
├── web/                          三端页面与静态资源
├── mp-weixin/                    游客小程序工程
├── assets/                       统一规格图片
├── data/                         运行时生成的 SQLite 数据库
└── tests/                        端到端验收脚本
```

约定：`server/`、`web/`、`assets/`、`docs/`、`mp-weixin/`、`tests/` 为源码目录，可纳入版本管理；`data/plum.db` 与 `server/__pycache__/` 为运行时产物，不应提交。

## 3. 安装步骤

### 3.1 检查 Python

```powershell
python --version
```

需要 3.10 或以上。Windows 若提示找不到命令，安装 Python 时勾选「Add Python to PATH」后重新打开终端。

### 3.2 安装依赖

使用一键脚本时会自动安装。手动安装：

```bash
python -m pip install -r requirements.txt
```

（可选）使用虚拟环境隔离：

```powershell
# Windows PowerShell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

```bash
# macOS / Linux
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
```

使用虚拟环境时，把后文的 `python` 换成 `python3`（macOS / Linux），并确保虚拟环境已激活。

### 3.3 首次启动

```bash
python start.py
```

首次启动会自动完成：创建 `data/` → 建 21 张表 → 灌入基准数据 → 监听 8080 → 打开门户页。控制台会打印各表记录数与三端地址。

## 4. 启动参数与访问

| 命令 | 效果 |
| --- | --- |
| `python start.py` | 默认 8080、保留数据、自动开浏览器 |
| `python start.py --reset` | 先重建基准数据（清掉手工新增的数据） |
| `python start.py --port 9000` | 换端口；小程序切到 `local` 时同步改 `mp-weixin/config/index.js` 的 `ENVS.local.baseUrl`，验收脚本改 `BASE` |
| `python start.py --no-browser` | 服务器场景下不打开浏览器 |
| `start.bat`（Windows 双击） | 等价 `python start.py`，附带自动装依赖 |

| 地址 | 用途 |
| --- | --- |
| `http://127.0.0.1:8080/` | 门户导航（角色入口，PC 桌面） |
| `http://127.0.0.1:8080/consumer` | 消费者 PC 站（桌面版浏览与交易） |
| `http://127.0.0.1:8080/biz` | 商户 PC 工作台（桌面版核销与供给管理） |
| `http://127.0.0.1:8080/admin` | PC 管理后台 |
| `http://127.0.0.1:8080/visitor` | 游客 H5（手机） |
| `http://127.0.0.1:8080/merchant` | 商户 H5 工作台（手机） |
| `http://127.0.0.1:8080/health` | 健康检查（返回各表记录数与模块列表） |

服务绑定 `0.0.0.0`，同一局域网内把 `127.0.0.1` 换成本机 IP 即可用手机访问 H5。

**PC 站与 H5 的区别**：`/consumer`、`/biz` 不是把 480px 的 `mobile-wrap` 拉宽，而是各自的桌面框架——消费者站用顶部横排导航 + 卡片网格/表格切换 + 主从双栏详情；商户站用侧栏 + 顶栏 + 数据表格 + 居中弹层表单 + 批量操作。两者复用同一套 `/api`、`/api/merchant` 接口与状态机，不新增后端业务逻辑。

**登录态按端隔离**：`common.js` 的 `Session` 按访问路径写入 `plum_consumer_sid` / `plum_biz_sid` / `plum_admin_sid` / `plum_visitor_sid` / `plum_merchant_sid`，同一浏览器可同时登录消费者、商户与管理员；门户页用 `Session.all()` 只读列出已登录身份。后端 `require_login(*roles)` 仍是权限最终防线，登录时传 `role` 会提前拦住串号。

## 6. 小程序导入与真机预览

### 6.1 默认：本地模拟数据（不需要启动服务）

1. 微信开发者工具 → 「导入项目」→ 目录选择 `mp-weixin/`。
2. 工程已配置开发者工具测试号 `touristappid`，导入时不需要填写任何账号信息。
3. 点「编译」。首页直接由 `mock/server.js` 供数，登录、分页、下单、预约、集章、错误态全部真实生效。
4. 「我的 → 去登录」用 `tourist01 / tourist123`（登录页有一键填入）。小程序不会自动登录，也不复用 H5 / PC 后台的登录态。
5. 「我的 → 设置 → 故障注入」可模拟 401 / 500 / 网络断开 / 慢网络，用来验收自动跳登录、重试与错误提示。

### 6.2 接真实后端

1. 保持 `python start.py` 运行（默认 8080）。
2. 「我的 → 设置 → 数据源」切到 `local`（`http://127.0.0.1:8080`）。切换会清掉旧环境的会话与业务缓存，保留收藏；业务代码零改动。
3. 「详情 → 本地设置」勾选**不校验合法域名、web-view、TLS 版本以及 HTTPS 证书**（本地 HTTP 服务必须）。`project.config.json` 已设 `urlCheck: false`。
4. 下拉刷新即可看到 SQLite 里的真实数据；演示账号与 2.2 节后端一致。

也可在代码里固定环境：改 `mp-weixin/config/index.js` 的默认 `mock`，或运行时 `require('./config/index.js').setEnv('local')`。

### 6.3 真机预览

「我的 → 设置 → 改局域网地址」填入 `http://<电脑局域网IP>:8080`（例如 `http://192.168.1.8:8080`），再把数据源切到 `lan`，手机与电脑连同一 Wi-Fi，防火墙放行 8080。`config.asset()` 会基于同一个 `baseUrl` 补全图片地址，改一处即可。

注意 `local` 的 `127.0.0.1` 在手机上指的是**手机自己**，真机上必然连不上；`urlCheck: false` 只在微信开发者工具生效，真机仍会校验合法域名并要求 HTTPS。局域网 HTTP 无法配置成合法域名，开发阶段需要在手机微信里点「…」→「打开调试」跳过校验；正式发布必须换成 HTTPS 域名，并在小程序后台配置 `request` / `downloadFile` 合法域名。默认 `mock` 不需要上述任何配置。

小程序里的点位图由包内本地地形底图（`images/map_base.jpg`）叠加 CSS 点位构成，不调用任何在线地图，不需要地图凭据；底图随包分发，`mock` 断网环境照常显示。业务图片已压缩打包到 `images/photos/`（由 `tools/build_mp_photos.py` 生成），默认 `mock` 即显示真实图片；远程图加载失败会自动降级到包内同名图，仍失败才回落到 CSS 占位块，因此不会出现破图。首页接口不可达时用 `api.getHomeOffline()` 兜底，界面不会空白。验收脚本见 `tools/gen_map_base.py`、`tools/verify_map.py`、`tools/verify_mp_images.js`。

网页端地图由 `web/assets/map.js` 渲染，门户 `/`、游客 H5 `/visitor` 与 PC 消费者站 `/consumer` 共用同一张 `web/assets/map_base.jpg` 和小程序的 `PIN_ANCHORS`，视觉与点位完全一致；需经 Flask 的 `/web/<name>` 路由访问，不能直接用 `file://` 打开 HTML。

## 7. 验收

```bash
python tests/smoke_test.py
```

脚本会在开始时重置基准数据，因此**建议在服务刚启动或允许数据被重置时运行**。它会打印每一项的通过/失败，最后输出总数与退出码。若某项失败，先按下方排错表处理，再用 `python start.py --reset` 重启后复跑。

小程序工程可独立验收，不需要启动服务、不需要微信开发者工具，只需 Node：

```bash
node tests/mp_weixin_smoke.js
```

脚本用最小 `wx` 实现加载 `mp-weixin/` 里的真实模块，检查 `app.json` 页面注册与四文件齐全、tabBar 引用、WXML 事件是否都有对应方法、WXML 是否含复杂表达式，然后依次跑通模拟服务端的分页 / 搜索 / 登录鉴权 / 幂等下单 / 预约 / 报名 / 订房 / 集章 / AI，以及配置化请求层的异步链路与 401、网络断开故障注入。退出码 0 表示全部通过，当前 **23 项全部通过**。

手工验收清单与逐功能验收标准见 `docs/开发任务书.md` 第 9 节。

## 9. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `start.bat` 一闪而过 | Python 不在 PATH 或依赖装不上 | 命令行执行 `python start.py` 看具体报错 |
| `ModuleNotFoundError: flask` | 依赖未装到当前解释器 | `python -m pip install -r requirements.txt`；虚拟环境需先激活 |
| `Address already in use: 8080` | 端口被占用 | 换端口 `--port 9000`，或结束占用进程 |
| 页面能开但列表空白、控制台报 401 | 服务重启后会话失效 | 刷新页面重新登录；各端独立，只需重登当前这一端 |
| `/consumer` 或 `/biz` 返回 404 | 服务还是旧进程，新增路由没加载 | 停止后重新 `python start.py`（`start.py` 用 `debug=False`，不会热重载） |
| PC 站切到另一端被要求重新登录 | 按端隔离是预期行为，不是串号 | 门户页可看到当前已登录的全部身份；各端独立登录即可 |
| PC 站在小屏上表格挤、出现横向滚动条 | 桌面版主形态是 ≥1366px | 992–1199px 侧栏会自动收成图标条，<768px 给出跳转对应 H5 的引导条；表格本身允许 `.table-wrap` 内横向滚动 |
| 后台图表空白 | 近 7 天无数据 | `python start.py --reset` 重建基准数据 |
| 图片显示占位图 | 素材文件缺失或路径不对 | 确认 `assets/` 下有 33 个文件；检查 `/assets/<文件名>` 能否直接打开 |
| `/web/common.css` 404 | 资源路径写错 | HTML 里必须写 `/web/common.css`，不要写 `/web/assets/common.css` |
| 小程序「连不上服务」 | 数据源已切到 `local`/`lan`，但服务未启动 / 地址不对 / 未勾选不校验合法域名 | 逐项确认；浏览器先访问 `/health` 验证服务；只想本地演示就在「我的 → 设置」切回 `mock` |
| 小程序一直跳登录页 | 会话过期，或故障注入还停在 401 | 「我的 → 设置 → 故障注入」改回「正常」，再用 `tourist01 / tourist123` 登录 |
| 小程序「我的」显示别人的昵称 | 用非游客账号登录了 H5 / 后台，或缓存了旧会话 | 小程序会话独立存储且强制校验游客角色；「我的 → 设置 → 退出登录」后重新用游客账号登录 |
| 真机预览全部失败 | 手机把 `127.0.0.1` 当成自己 | 数据源切 `lan`，在「我的 → 设置 → 改局域网地址」填电脑的局域网 IP |
| 验收脚本某项失败 | 手工操作改过基准数据 | 用 `--reset` 重启服务后复跑 |
| Windows 下重置数据库报占用 | 数据库文件被其它进程打开 | 关闭 SQLite 查看器；`init_db(force=True)` 已改为逐表 DROP，正常无需删文件 |
